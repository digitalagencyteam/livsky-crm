# LIVSKY CRM

Админка агентства для одного человека — админа. Стиль тот же, что у сайта: биом, стекло, Manrope + Unbounded.

| Раздел | Что внутри |
|---|---|
| **Бухгалтерия** | «Доска клиентов» из KOMETA CRM без изменений логики: клиенты в работе и ушедшие, услуги по месяцам, выручка, расходы, прибыль, маржа, невыплаченное, периоды (месяц, 3/6 месяцев, год, всё время, свой) |
| **Договоры** | Две вкладки — клиенты и сотрудники. PDF хранятся в CRM (проект, подписанный скан, приложения). Поиск — по стороне, номеру, предмету, заметкам и **по тексту внутри PDF** (логика «Архива»). Статусы: черновик → на подписи → подписан → закрыт. Загрузили подписанный скан — договор сам становится «Подписан» |
| **Заявки** | Всё, что приходит с сайта: форма «Обсудить проект» и бронь звонка (с датой, временем МСК и площадкой). Статусы, заметки, поиск. О новой заявке — письмо на почту и (по желанию) сообщение в Telegram. Счётчик новых — в меню |
| **Сайт** | Статьи: вставили текст → статья собралась по разделам (оглавление, таблицы, цитаты, картинки, советы, чек-листы, тесты), справа живой предпросмотр. Кейсы: форма по шаблону страницы кейса сайта, видео/картинки, привязка к услугам. RU обязателен, EN по желанию (без перевода сайт покажет русский). Публикуете — сайт обновляется сам |

## Устройство

```
livsky-crm/
├── server/   API: Express + Prisma + PostgreSQL (из kometa-crm-back: авторизация, бухгалтерия)
├── web/      админка: React + Vite + Tailwind (из kometa-crm: UI-кит и бухгалтерия, перекрашены под LIVSKY)
└── shared/   общее для обоих: разбор текста статьи, справочник услуг сайта
```

Почему отдельный проект, а не внутри сайта: CRM нужны свой сервер и база, финансы и договоры не должны жить в коде
публичного сайта, а сайт остаётся быстрым и может дальше собираться статикой. Сайт берёт из CRM статьи и кейсы
и шлёт туда заявки через публичное API (`/api/public`).

## Запуск локально

```bash
# 1. База (любой PostgreSQL 14+), например через Docker:
docker run -d --name livsky-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:16
docker exec livsky-pg createdb -U postgres livsky_crm

# 2. API
cd server
cp .env.example .env              # DATABASE_URL уже на этот Postgres
npm install
npx prisma migrate deploy         # таблицы
npm run seed:admin                # админ agencyworkemailone@gmail.com, базовый пароль из .env
npm run import:site -- ../../website   # перенести готовые статьи и кейсы сайта (путь к папке сайта)
npm run dev                       # http://localhost:4000

# 3. Админка (в другом терминале)
cd web
npm install
npm run dev                       # http://localhost:5173 — /api проксируется на :4000
```

**Вход:** `agencyworkemailone@gmail.com`, базовый пароль `Livsky2026!` (или ваш `ADMIN_PASSWORD`).
При первом входе CRM попросит сменить его на свой. Забыли пароль — «Забыли пароль?» на входе: код придёт на почту
(нужен SMTP, см. ниже; без него код печатается в лог сервера).

Тесты сервера: `cd server && npm test` (правила бухгалтерии, разбор статей, проверки форм, маршруты, контент для сайта).

## Почта (Gmail)

1. В аккаунте `agencyworkemailone@gmail.com` включите двухэтапную аутентификацию.
2. Создайте «Пароль приложения»: https://myaccount.google.com/apppasswords
3. В `.env` сервера: `SMTP_PASS=<этот пароль>`. Остальное уже заполнено в `.env.example`.

Telegram (необязательно): создайте бота у @BotFather → `TELEGRAM_BOT_TOKEN`, напишите боту что-нибудь
и возьмите свой chat id (например у @userinfobot) → `TELEGRAM_CHAT_ID`.

## Файлы (Cloudflare R2)

Без R2 файлы пишутся в `server/uploads/` — это только для разработки (на Render диск стирается при деплое).
Для боевого: бакет R2 → ключи `R2_*`, и **публичный домен** бакета для картинок/видео сайта → `R2_PUBLIC_URL`.
Договоры лежат под `contracts/` и открываются только через API после входа — прямой ссылки на них нет.

## Деплой

- **API + база** — Render: `render.yaml` в корне (Blueprint). После создания заполните переменные с пометкой `sync: false`,
  затем в Shell сервиса: `npm run seed:admin` и (один раз) `npm run import:site` — для импорта положите рядом папку сайта
  или выполните импорт локально, указав `DATABASE_URL` боевой базы.
- **Админка** — Vercel: Root Directory `web`, переменная `VITE_API_URL=https://<api>.onrender.com/api`.
  В `CLIENT_URL` сервера — адрес админки.

## Подключение сайта

В `.env` сайта (`website/.env.example` уже дополнен):

| Переменная | Значение |
|---|---|
| `API_URL` | `https://<api>/api/public` — статьи и кейсы из CRM, заявки уходят в CRM |
| `REVALIDATE_SECRET` | тот же, что `SITE_HOOK_SECRET` в CRM |
| `MEDIA_HOST` | домен `R2_PUBLIC_URL` без `https://` (картинки из CRM через next/image) |
| `NEXT_PUBLIC_LEADS_URL` | только для статической сборки: `https://<api>/api/public/leads` |

В CRM: `SITE_HOOKS=https://livsky.ru/api/revalidate` — после публикации сайт сбрасывает кэш нужных страниц.
Для статической сборки (GitHub Pages) в `SITE_HOOKS` ставится deploy hook хостинга — сайт пересоберётся.
`SITE_ORIGINS` — адреса сайта, с которых браузер может слать заявки.

Пока `API_URL` у сайта пустой, сайт работает на своих моках, как раньше.

## Разметка статьи

| Пишете | Получаете |
|---|---|
| `## Раздел` | новый раздел (пункт оглавления) |
| пустая строка | новый абзац |
| `> Цитата — Автор` | цитата |
| `\| A \| B \|` | таблица, первая строка — шапка |
| кнопка «Картинка» или вставка скриншота Ctrl+V | картинка |
| `!! Совет: Заголовок` + текст | блок-совет (`!! Важно:` — предупреждение) |
| `Заголовок:` + строки `[ ] пункт` | интерактивный чек-лист |
| `?? Вопрос` + `- вариант` / `+ верный` / `= пояснение` | мини-тест |
| `:::` JSON `:::` | любой блок сайта: калькулятор, график, цифры (так переносятся готовые статьи) |

Текст до первого `##` — вступление: кнопка «Взять вступление из текста» сделает из него анонс.
